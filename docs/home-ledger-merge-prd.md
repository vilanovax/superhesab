# PRD: ادغام قالب شخصی و خانواده (خانه)

## تصمیم

قالب‌های `PERSONAL` و `FAMILY` از نظر محصول **یکی** می‌شوند تحت نام **خانه**.

- **فاز ۱ (همین سند):** یک لجر؛ تک‌نفره یا چندنفره (تا ۸)؛ بدون تسویه؛ بدون حریم خصوصی per-category.
- **فاز ۲:** حریم خصوصی per-category — [`docs/home-category-privacy-prd.md`](./home-category-privacy-prd.md) ✅ (MVP)
- **`PARTNER` (حساب مشترک)** جدا می‌ماند: دونفره + تسویه.

## مدل ذهنی کاربر

| نیاز | قالب |
|------|------|
| دخل‌وخرج من / خانه (با یا بدون همسر و خانواده) | **خانه** (`FAMILY`) |
| دو نفر + «کی بدهکاره» | **مشترک** (`PARTNER`) |
| سفر گروهی + تسویه | **سفر** |

تک‌نفره = همان خانه با یک عضو. دعوت همسر/اعضا همان لجر را اشتراکی می‌کند (همه می‌بینند).

## تغییرات فنی فاز ۱

1. نوع کانونیکال ذخیره: `FAMILY` (لیبل UI: «خانه»).
2. `UPDATE Space SET type = 'FAMILY' WHERE type = 'PERSONAL'`.
3. ساخت دفتر جدید: گزینهٔ «شخصی» حذف؛ «خانه» جایگزین خانواده/شخصی.
4. ورودی‌های قدیمی `PERSONAL` (فرم، بک‌آپ، API): به `FAMILY` coerce می‌شوند.
5. `getTemplate("PERSONAL")` → رفتار `FAMILY` (سازگاری خواندن).
6. enum `PERSONAL` در Prisma/TypeScript **حذف نمی‌شود** (سازگاری بک‌آپ قدیمی).

## خارج از اسکوپ فاز ۱

- حریم خصوصی دسته / تراکنش
- حذف enum `PERSONAL` از schema
- ادغام با `PARTNER`
